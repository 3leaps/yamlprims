## yamlprims v0.3.1

Patch release of `yamlprims` with a fix in the pure-Go module. The library contract is still `spec-v1.6`. The specification text in this tree is the revision 1.7 draft (`SPEC_VERSION` 1.7), which this release does not implement; revision 1.7 ships with a later minor release. The Rust crate, the CLI, and the Python and TypeScript packages are rebuilt at the new version with no behavior change.

### What it ships

- **Pure Go:** loading a block scalar whose content is indented 14 or more columns no longer fails to terminate when the input ends inside that indentation. `Load`, `LoadAll`, and every other Go load entrypoint were affected in v0.1.0 through v0.3.0. The Rust crate and the Python and TypeScript packages, which use the Rust core, were not affected.
- **Conformance:** six new in-repo vectors cover the indentation boundary and chomping (`194` vectors, byte-for-byte across Rust, Go, TypeScript, and Python), and a Go regression test checks indentation widths 1 to 40 under a time limit.

### Verification

The `yamlprims` CLI parses, lints, emits, and projects YAML; it verifies no cryptographic signatures and embeds no keys. To verify this release, verify the annotated OpenPGP-signed `v0.3.1` tag and the dual-signed checksum manifests (`SHA256SUMS` and `SHA512SUMS`, signed with both Minisign and the OpenPGP release signing subkey) against the public pins committed in the tagged tree (`docs/security/` and `keys/expected-fingerprints.txt`); see [docs/security/README.md](../security/README.md) and [RELEASE_CHECKLIST.md](../../RELEASE_CHECKLIST.md).
